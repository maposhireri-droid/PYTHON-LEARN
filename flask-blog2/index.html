A Git Log of Learning to Code

Every commit here is a real step — a concept that finally clicked, a grader that finally passed, a bug that finally made sense. Four commits in. Many more to come.

a1e4f92 tag: week-1

init: learn dictionaries & sets

expand ▾
Author: Keirano <learning@self> · foundations

The early days were full of the kind of mistakes that feel embarrassing in the moment and obvious in hindsight. What's the difference between {1, 2} and {1: 2}? Why does setdefault behave the way it does? How do you safely remove a key from a dictionary without your program blowing up?

These weren't glamorous questions, but they were the right ones. Data structures are the vocabulary of programming — you can't write sentences until you know the words, and dictionaries and sets turned out to be words I used constantly once I understood them.

7c2b810 tag: week-3

feat: build the budget app

expand ▾
Author: Keirano <learning@self> · first real project

Eventually the concepts needed a project to live in. I built a budget tracking app — a Category class with ledger methods, deposits, withdrawals, transfers between categories, and a create_spend_chart function that turned raw numbers into a bar chart made of characters.

This is where I learned that almost working and working are two very different things. Getting the spacing exactly right in a text-based chart, matching an automated grader's exact expectations, wrestling with Git authentication just to push the thing to GitHub — none of it was covered in a tutorial. It was just persistence, one error message at a time.

e91fa3d tag: week-6

feat: think in objects

expand ▾
Author: Keirano <learning@self> · OOP fundamentals

From there, things got more interesting. I moved into object-oriented programming in earnest — building an email simulation with Email, User, and Inbox classes that could send, receive, and list messages. Then an Employee class with property setters, a custom __repr__, and shared class-level salary data.

This is where OOP stopped being an abstract idea and started clicking. A class isn't just a container for data — it's a way of describing what something is and what it can do. Property setters taught me about controlling access to data. __repr__ taught me that how your objects present themselves matters. Debugging grader failures taught me the most important lesson of all: the computer does exactly what you tell it, not what you meant.

4b6d1af tag: ongoing

docs: what I've learned about learning

expand ▾
Author: Keirano <learning@self> · reflection

If there's a theme running through all of this, it's that progress in programming rarely feels like progress while it's happening. It feels like staring at an error message, googling a stack trace, or squinting at an f-string wondering why self.sender.name isn't producing what you expected. The learning happens in retrospect — you look back a few weeks later and realize the thing that used to stump you is now just... obvious.

I'm still early in this journey. There's a lot I don't know yet. But I've got a growing GitHub repo, a habit of reading error messages instead of fearing them, and enough small wins stacked up to know I'm headed somewhere.
